# Развёртывание на VPS

Комплект рассчитан на сервер с российским центром обработки данных: 2 vCPU,
2 ГБ памяти, 20 ГБ диска. Этого достаточно для демонстрационного стенда
и для работы отдела из 10–20 человек.

## Что нужно

| Ресурс | Стоимость | Комментарий |
|---|---|---|
| VPS 2 vCPU / 2 ГБ | около 560 ₽/мес | подходит минимальный тариф |
| Домен .ru | 747 ₽ первый год | продление дороже — от 3 075 ₽/год |
| Docker и Docker Compose | бесплатно | ставятся из репозитория дистрибутива |

## Порядок

1. Установить Docker и Docker Compose:
   `curl -fsSL https://get.docker.com | sh`
2. Скопировать комплект на сервер: `scp accent-crm-stand.zip root@host:/opt/`
   и распаковать в `/opt/crm`.
3. Создать `.env` из `.env.example`, задать пароли базы и администратора,
   указать `SITE_URL=https://crm.example.ru`.
4. Поднять систему: `docker compose up -d`. Первый запуск занимает 2–3 минуты.
   Порты контейнера EspoCRM слушают только `127.0.0.1`.
5. Дождаться строки `Installation completed successfully`:
   `docker compose logs -f espocrm`.
6. Наполнить демо-данными одним из способов:
   - `bash deploy/restore.sh` — 30 обращений из дампа; учётные записи и их
     пароли приходят из дампа, пароль администратора из `.env` после этого
     не действует;
   - `python seed_demo.py --url https://crm.example.ru --user admin --password <из .env>`
     — данные создаются заново, доступы остаются известными.
7. Направить A-запись домена на адрес сервера.
8. Выпустить сертификат: `certbot --nginx -d crm.example.ru` (или средствами
   хостера). Порт 8080 наружу не публиковать — только 80 и 443 через прокси.
9. Проверить вход: `https://crm.example.ru`, учётная запись `admin`
   с паролем из `.env` (если стенд разворачивался без `restore.sh`).
10. Настроить резервное копирование: `crontab -e`, строка
    `15 3 * * * cd /opt/crm && bash deploy/backup.sh`.

## Обслуживание

- Резервная копия — `deploy/backup.sh`: дамп базы без таблиц `auth_token`
  и `auth_log_record` и архив каталога данных, хранение 14 дней. Архив
  каталога данных содержит `config-internal.php` с паролем базы и ключом
  шифрования, поэтому хранить его можно только на защищённом носителе
  и нельзя прикладывать к отчётам и публиковать.
- Обновление — `docker compose pull && docker compose up -d` после бэкапа.
- Восстановление — `deploy/restore.sh [файл дампа]` в чистую установку.

## Ограничения стенда

Данные вымышленные. Реальных клиентов и персональных данных организации
на стенде нет, поэтому требования 152-ФЗ к обработке не возникают. Перед
переносом рабочей базы организации нужно уведомление Роскомнадзора
и российский ЦОД — он уже выбран.
